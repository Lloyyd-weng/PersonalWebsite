HSL の「明度」は、色相を変えると体感が大暴れする黄のあたりはまぶしく、青のあたりは真っ暗。数字は同じ 50% なのに

HSL の L は、
人の目を見ていない。

RGB の数字を平均しているだけで、明るさの「体感」とは無関係。
だから lighten() や「hover で 5% 明るく」が色相ごとに壊れる。

OKLCH とは

ツマミ 3 本 ＝
立体の中の「住所」

L は高さ、C は軸からの距離、H は角度 — 円柱座標そのもの。
1 本だけ動かしても、ほかの 2 本は釣られません。

OKLCH とは

L=高さ・C=軸からの距離・H=角度
oklch(0.70 0.120 250) #61a3e6
L　高さ（0–1）0.70
C　軸からの距離（0–0.4）0.120
H　角度（0–360°）250°

ドラッグで回転。いまの色相のところで
切り開いてあります — H を回すと切り口も回る。

ただし

HSL から「そのまま引っ越し」はできない

色相の番地が違う

0° は赤じゃなくてマゼンタ。HSL の角度をそのまま持ってくると全部ずれる。

赤 29° 黄 90° 緑 142° 青 264° マゼンタ 328°

C の天井は波打っている

出せる鮮やかさの上限は色相ごとに全然違う（L=0.7 のとき、緑 0.236 / シアン 0.127）。

「全部の色を C=0.2 で統一」は物理的に無理な色相がある足りない分はブラウザが勝手に近い色へ丸める（エラーにはならない）

ドラッグで回転。sRGB 補間は空間を最短で突っ切り、 無彩色の軸のそばをかすめる——それが泥の正体。 RGB 立方体に切り替えると、こんどは sRGB 補間のほうが直線になる。

今日から使える ②

1 色から、状態色を全部「計算」する

.btn:hover    { background: oklch(from var(--brand) calc(l + 0.08) c h); }
.btn:active   { background: oklch(from var(--brand) calc(l - 0.06) c h); }
.btn:disabled { background: oklch(from var(--brand) l calc(c * 0.25) h); }
.btn:focus    { outline-color: oklch(from var(--brand) l c h / 0.4); }
hover active disabled focus
ブランド色を差し替えても、hover も disabled も勝手についてくる注意：l は 0–1 の数値。calc(l - 10%) は無効、calc(l - 0.1) と書く

ハマりどころ

覚えて帰るのは 2 つだけ

1

同じ L ≠ 同じコントラスト

WCAG は別の物差しで測る。同じ L=0.62 でも色相で 3.45〜3.90 までばらつく。4.5 ギリギリの色は必ず実測。

3.90赤 3.66黄 3.70青 3.45緑
2

L=0.5 は中間グレーじゃない

目は暗い側に敏感なので、「体感の半分」は物理的にはかなり暗い。HSL の数字をそのまま移すと全体が沈む。

oklch(0.5 0 0)
= #636363
#808080 は
L ≒ 0.60
