# 色覚のしくみメモ：三つの数・二つの通路

2026-09-03。OKLCH deck（`public/slides/oklch/index.html`）の質疑から起こした素材メモ。
2026-09-03 追記:下の #1・#2・#4 は deck の 14–16 枚目として実装済み(「なぜこの形？」章、輝度の内訳の直後)。#3・#5 は未実装のまま。
同日、MacAdam(旧 7 枚目)と色度図・色域比較(旧 18 枚目)は deck から外した——今回の発表は縦(輝度)の歪みだけを扱い、横の凸凹の話はしない。このメモの横方向の議論はそのまま残す(発表では使わない素材)。以下の「deck N 枚目」は削除後の番号。

主題は一本:**目は波長を測っていない。光のスペクトルを三つの数に潰し、その三つを
二つの通路に分けて使っている。** deck の既存ページはこの一本の別々の断面を見ている
——同色異譜（色度側）と輝度の内訳（明るさ側）が別ページにあるのは、この分岐が理由。

数値は全部このメモを書いた時点で計算して確かめたもの。出どころは各節に書いた。

## 1. 土台：単変量原理（univariance）

錐体は三種類:

| | ピーク波長 | 通称 | 全錐体に占める割合 |
|---|---|---|---|
| S | ~420nm | 青 | 約 5–10% |
| M | ~534nm | 緑 | L と合わせて 90% 超 |
| L | ~564nm | 赤（実際のピークは黄緑） | 〃 |

**一個の錐体が返すのは、スカラー一個だけ。** 自分の感度曲線で重みをつけて光子を
数えた総和であって、波長の情報はそこで消える。だから**錐体単体は色盲**——
「感度の高い波長が少し」と「感度の低い波長がたくさん」を区別できない。

これが univariance。色覚のいちばん下の石。

帰結:**無限次元のスペクトルが三つの数 (L, M, S) に射影される。** 情報はここで
永久に落ちる。下流の神経系がどう頑張っても戻せない。

## 2. 同色異譜（metamer）

(L, M, S) が同じなら同じ色。分光計は一瞬で見分けるが、目には**区別する手段が
そもそも存在しない**。

### なぜ黄が「赤＋緑」で作れるのか

鍵は **L と M の感度曲線が猛烈に重なっている**こと。ピークが 30nm しか離れて
いない（534 / 564）ので、**M だけを叩いて L に触らない波長が存在しない**。

- 580nm 単色光 → `(L 高, M 高, S ≈ 0)`
- 赤 630nm ＋ 緑 530nm → 強度比を調整すると同じ `(L 高, M 高, S ≈ 0)` が作れる

三つの数が同じ ＝ 同じ色。「似ている」ではなく、**この測定系における同一の測定結果**。

### 画面の黄は完全な黄ではない（計算値）

sRGB の `#ffff00` は xy = (0.419, 0.505)。白点 D65 から引いた延長線が軌跡と
交わる点を求めると:

```
主波長   = 570.4 nm
励起純度 = 79 %        （100% = 単波長）
```

同じ色相方向だが、ナトリウム灯の黄より一段淡い。理由は幾何:
**二原色の混合は必ず両者を結ぶ直線上に載る。馬蹄形の縁は曲線。直線は常に曲線の内側。**
sRGB 三角形が馬蹄形を食べ切れないのと同じ理由（deck から外した色域比較ページの話とここが繋がる）。

### 逆向きの帰結:三原色ディスプレイが成立する理由

目がスペクトルをそのまま報告していたら、**RGB 画面は原理的に作れない**。
スペクトル分布ごと再現する必要が出るから。目が三つの数に潰してくれるからこそ
三原色で足りる。

**馬蹄形が二次元なのも同じ理由。** 色は三次元 (L,M,S)、そこから全体強度の一次元を
割ると二次元＝色度図。CIE 1931 の体系全体がこの一点の上に建っている。

### 対になる例:マゼンタには波長が無い

マゼンタ ＝ `L 高・S 高・M 低`。だが **M の感度曲線は波長軸上で S と L の間に挟まっている**。
長波は L を、短波は S を叩くが、**両端を同時に叩いて真ん中を飛ばす単一波長は存在しない**。
だからマゼンタは混合でしか作れない。虹にマゼンタが無いのはこのため。

馬蹄形の底の**直線（純紫軌跡）**が、この「波長を持たない色」の一群。
deck から外した色域比較ページの「紫の縁はもともと直線なのでマゼンタはほぼ無傷」——
マゼンタの C 天井 0.322 が六色中トップなのは、直線同士なので三角形が削り取れないから。

## 3. 分岐：三つの数は二つの通路に分かれる

**ここが要。** 網膜を出た直後に二系統へ分かれる。同じ三つの錐体を使うが、別の計算。

| | 色度通路 | 輝度通路 |
|---|---|---|
| 何を計算するか | 三つの数の**比** | 三つの数の**重み付き和** |
| 対抗形式 | L−M, S−(L+M) | ≈ L + M |
| **S 錐体（青）** | 参加する | **ほぼ寄与しない** |
| 産物 | 馬蹄形・同色異譜 | V(λ)・`Y = 0.2126R + 0.7152G + 0.0722B` |
| OKLCH でいうと | **C と H** | **L** |

### 青が暗い理由は「箱」ではなく「目」

輝度係数を各規格で計算した（原色 xy と D65 から RGB→XYZ 行列を組み、Y 行を取る）:

| 規格 | R | G | B |
|---|---|---|---|
| sRGB / Rec.709 | 21.3% | 71.5% | **7.2%** |
| Display P3 | 22.9% | 69.2% | **7.9%** |
| Rec.2020 | 26.3% | 67.8% | **5.9%** |
| Adobe RGB | 29.7% | 62.7% | **7.5%** |

**どの規格でも青は 5–8%。箱を替えても青は暗いまま。**
「青」という色相が住んでいる波長域では、目の輝度感度がすでに崖から落ちている
（V(λ) は 555nm を 1.0 として 450nm で約 0.038、**26 倍の差**）。

さらに構造的な理由が三つ:

1. S 錐体は全錐体の **5–10%** しかない
2. **中心窩のいちばん中心には S 錐体が一個も無い**（視野で最も解像度の高い部分は「青盲」）
3. 輝度を運ぶ magnocellular 通路は **L+M から配線されていて S を取らない**

つまり青は**色**の系にはちゃんと入る（鮮やかな青に見える）が、**明るさ**の系では
ほとんど票を持たない。

### deck の構造との対応

- ジャガイモの**縦**の歪み ＝ 輝度通路（目）→ deck 13 枚目
- ジャガイモの**横**の凸凹 ＝ 箱の三角形（ディスプレイ）→ deck から外した色域比較ページ
- ただし横を「測る物差し」を均等にしたのは色度通路側の補正（MacAdam → OKLab）
  → deck から外した MacAdam ページ・現 8 枚目

deck 11 枚目の旧タイトル「この歪みは、箱と目の合作」(現在は「角の高さが揺れるのは、目のせい」)は、正確には
**「縦は目の輝度通路、横は箱——ただし横を測れるのは色度通路が校正済みだから」**。

## 4. MacAdam 補正は「定規に刻まれている」（既出の確認）

質疑で出た論点。**MacAdam の補正はジャガイモの表面に瘤として見えるものではない。**
OKLCH を見ている時点で補正は座標系そのものに適用済み。輪郭に残っているのは
補正の**あと**に残ったもの（縦＝輝度係数、横＝三角形）。

補正が買ったものは:**「マゼンタは 0.322 まで、シアンは 0.155 まで」という比較が
成立すること自体。** xy 図の上ではこの二つの数は比較不能——それこそが楕円が
11 倍違うことの意味。

### 検算した数値（色相角の取り分・輝度正規化に依存しない指標）

光譜軌跡上の各波長帯が白点から見て張る角度:

| 波段 | xy 図 | OKLCH | 変化 |
|---|---|---|---|
| 青紫 450→490nm | 56.1° | 88.1° | **+57%** |
| 青緑 490→510nm | 61.9° | 25.8° | **−58%** |
| 緑 510→570nm | 65.6° | 54.8° | **−16%** |
| 橙赤 570→640nm | 66.5° | 89.0° | **+34%** |

MacAdam の楕円と一致する：最大の楕円は緑域（長半径 9.6×10⁻³ @ x=0.15,y=0.68）、
最小は青域（0.85×10⁻³ @ x=0.16,y=0.057）、比は約 11 倍。
**大きい楕円 ＝ xy 上で分不相応に広い ＝ 圧縮される。小さい楕円 ＝ 詰まっている ＝ 引き伸ばされる。**

### sRGB 六原色の OKLCH 実測値

| | 赤 | 黄 | 緑 | シアン | 青 | マゼンタ |
|---|---|---|---|---|---|---|
| C | 0.258 | 0.211 | 0.295 | **0.155** | 0.313 | **0.322** |
| L | 0.628 | 0.968 | 0.866 | 0.905 | 0.452 | 0.702 |
| H | 29° | 110° | 142° | 195° | 264° | 328° |

**立体の上で本当に潰れているのはシアン（0.155）で、緑ではない**（緑 0.295 は六色中三位、
青 0.313 とほぼ肩を並べる）。そしてシアンが狭いのは二つの理由の重ね合わせ:

1. 知覚側 — 青緑帯が色相円の取り分を 58% 失っている（上表）
2. 箱側 — sRGB 三角形が馬蹄形のシアンの膨らみを削る。Rec.2020 に替えると
   **シアンの天井は +99%、青は +7%**（deck から外した色域比較ページのデータ）

**登壇時の注意:**「シアンが狭いのは MacAdam のせい」と言い切ると色域比較ページ(外した)の話と衝突する。

## 演示ページのネタ

1. **単変量原理の体感**(→ deck 14 枚目)— 錐体一個分のシミュレータ。感度曲線を出して、
   「波長を変える」「強度を変える」の二つのスライダーで**同じ出力値**を作らせる。
   一個の錐体が色盲であることを手で確かめさせる。

2. **同色異譜マッチャー**(→ deck 15 枚目)— 左に単波長 580nm、右に赤＋緑の二本スライダー。
   (L,M,S) の三本バーをリアルタイム表示し、三本を揃えると左右のパッチが
   見分けられなくなる。「スペクトルは全然違うのに」を並べて出す。

3. **マゼンタ狩り**(未実装)— 波長スライダーを 380→700 まで舐めても
   マゼンタが一度も出てこないことを確かめさせる。そのあと二本の光を足すと出る。
   純紫軌跡がなぜ直線なのかがここで腑に落ちる。

4. **二つの通路の分岐図**(→ deck 16 枚目)— 一つのスペクトル入力 → 三錐体 → 二通路に分岐する
   ダイアグラム。S から輝度通路への線が**極細**なのが視覚的な主張。
   ランプの点け消しで両通路の出力が別々に動く。

5. **箱を替えても青は暗い**(未実装)— 上の輝度係数表をインタラクティブに。
   規格を切り替えても B の帯がほとんど伸びないことを見せる。
   deck 13 枚目(輝度の内訳)の直接の続き。

## 検算に使ったスクリプト

このメモの数値は全部 node で計算した。式は deck の `index.html` 内の
`okFromLin` / `xyzToLin` / `LOCUS` / `MACADAM` と同じ出どころ。再計算するなら:

- 輝度係数 — 原色 xy と白点から RGB→XYZ 行列を組み、その Y 行
- 主波長・純度 — 白点から目標色へ引いた半直線と `LOCUS` 折れ線の交点
- 色相角の取り分 — `LOCUS` の各点を Y=1 に正規化して OKLab へ入れ、
  `atan2(b, a)` の差を取る（色相角は輝度正規化に依存しないのでこの指標を選んだ）
- 六原色の OKLCH — sRGB 各角を linear 化して OKLab 行列 → `hypot(a,b)`
